Occupancy vs. TILE_SIZE

Theoretical model for gemm_thread_tile (TM=4) on an RTX 3080 Ti — 44 regs/thread, 65536 regs/SM, 1536 threads/SM, 16 max resident blocks/SM. TILE_SIZE 8 / 16 / 32 are the values actually built and benchmarked; the rest is the same formula extended across the full valid range.

Resident warps admitted, by limiting resource

Each line = how many warps would fit under that ONE resource alone (blocks admitted × warps/block). The lowest line at a given TILE_SIZE is the actual binding constraint — and it's what feeds directly into Chart 2's occupancy. Raw block count alone (not shown here) is misleading: small tiles admit many thin blocks, large tiles admit few fat ones, so block count and occupancy don't rank the same way.

Resulting occupancy

Occupancy = (blocks admitted × warps/block) / 48 max warps per SM. Red dots mark the three TILE_SIZE values actually compiled and run.

Formulas used

T = TILE_SIZE. All block-count terms are floored (a block only admits if it fully fits).

// per-block resource cost threads(T) = T * T warpsPerBlock(T) = ceil( threads(T) / 32 ) threadsRounded(T) = warpsPerBlock(T) * 32 // SM reserves whole warp slots smemBytes(T) = 4 * T * T * (TM + 1) // As[T*TM][T] + Bs[T][T], 4 bytes/float // max blocks admitted under EACH resource alone bThreads(T) = floor( threadsPerSM / threadsRounded(T) ) bRegs(T) = floor( regsPerSM / (regsPerThread * threadsRounded(T)) ) bSmem(T) = floor( smemPerBlock / smemBytes(T) ) bHw = maxBlocksPerSM // flat hardware cap, independent of T // binding constraint = smallest of the four b(T) = min( bThreads(T), bRegs(T), bSmem(T), bHw ) // Chart 1 plots each limiter in WARP terms (not raw blocks) -- // this is what's actually comparable to the 48-warp/SM ceiling: wThreads(T) = bThreads(T) * warpsPerBlock(T) wRegs(T) = bRegs(T) * warpsPerBlock(T) wSmem(T) = bSmem(T) * warpsPerBlock(T) wHw(T) = bHw * warpsPerBlock(T) // Chart 2: resulting occupancy occupancy(T) = ( b(T) * warpsPerBlock(T) / maxWarpsPerSM ) * 100% // Why wThreads/wRegs zigzag instead of declining smoothly: // both reduce to the same sawtooth shape, floor(ceiling / w) * w, // where w = warpsPerBlock. It only touches "ceiling" when w divides // evenly into it; otherwise flooring wastes some of the budget. wThreads as f(w) = floor( 48 / w ) * w // ceiling = maxWarpsPerSM wRegs as f(w) = floor( 46.5 / w ) * w // ceiling = regsPerSM / (regsPerThread * 32)

Constants used (this GPU, this kernel): TM=4, regsPerThread=44, regsPerSM=65536, threadsPerSM=1536, maxWarpsPerSM=48, smemPerBlock=49152 bytes, maxBlocksPerSM=16. Register count confirmed via nvcc -arch=sm_86 -Xptxas -v; the rest via cudaGetDeviceProperties.

Model assumes ~constant register usage across TILE_SIZE (confirmed empirically: 44 at TILE_SIZE=16, 44 at 32, 47 at 8). Non-multiple-of-32 thread counts round up to full warp slots, which is why a few odd TILE_SIZE values show local dips. This is a simplified model of block admission — Nsight Compute's measured occupancy (e.g. 73% at TILE_SIZE=16 vs this model's 83.3%) differs slightly due to real register allocation granularity the model doesn't capture.
